修两条会吞用户数据的路径（这次接口配置丢失就是它们干的）
1. npm run build 原本第一件事是 rmSync(dist)，把用户存在 dist\...\data 里的
   接口配置和对话一起删了。现在打包前先把 data 挪出去、重建完原样放回，
   并在检测到数据时打印提示。
2. store._read() 原本 try{JSON.parse}catch{return defaultState()}：只要 data.json
   带个 UTF-8 BOM（记事本 / Set-Content -Encoding UTF8 都会写）或者稍微损坏，
   就会被当成空数据，**紧接着一次保存把用户配置覆盖没**。现在：
   - 读之前去掉 BOM，带 BOM 的文件能正常读回来
   - 解析失败时把原文件另存成 data.json.unreadable-<时间>，并在界面上弹警告
   - 空白文件按首次运行处理，不算损坏
   - 导入备份的 parseBackup 同样防 BOM
3. 数据目录选择改为「优先沿用已经有 data.json 的那个目录」，
   避免可写性变化导致程序换目录、看起来像数据丢了
